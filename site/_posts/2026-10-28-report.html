跟进 2026-10-26 的 PHP2Shell 在野报道：CISA 于周一正式确认这两个近期已修补的 PHP 缺陷存在在野利用，并把 CVE-2026-109618 与 CVE-2026-109619 收进已知被利用漏洞目录（KEV）。两枚缺陷评分均为 9.2，均可造成未认证远程代码执行，其中 CVE-2026-109618 为 out-of-memory 类问题。

CVE-2026-109618CVSS 9.29 源报道
Impact

暴露人群是所有对外提供 web 请求的 PHP 部署；入选 KEV 把优先级从厂商通告提升到美国联邦限期处置口径，也意味着这条缺陷已不是理论风险，未打补丁的实例应直接按已暴露处理。

LiteLLM 低权限用户可伪造凭据提权至 Proxy Admin

GitHub 通告 CVE-2026-114612（CVSS 9.9，high）：LiteLLM Proxy 把同一把 salt key 同时用于密封静态 secrets 与签发会话令牌，持有 internal_user 权限的已认证用户可在申请 API key 时于构造的 metadata 字段里放入伪造的管理凭据，从而升级为 proxy_admin 并达成远程代码执行。修复版本 1.100.4、1.101.3、1.102.2。

CVE-2026-114612CVSS 9.9
受影响 litellm修复 1.100.4, 1.101.3, 1.102.2
Impact

暴露人群是自建 LiteLLM 网关并开放内部账号的组织——这类网关通常集中存放各家模型的 API key 与云侧凭据；密钥跨用途复用使单个低权限账号即可换来管理员身份与代码执行，等于把整个密钥库与下游模型调用交出去。

Action

升级 litellm 至 1.100.4、1.101.3 或 1.102.2；收紧 internal_user 权限账号范围，排查异常签发的 API key 与会话令牌，并轮换被同一把密钥覆盖的 secrets 与令牌材料。

Authlib 空签名 JWS 被当作已验签

GitHub 通告 CVE-2026-96760（CVSS 9.1，critical）：Authlib 1.9.0 之前的 JsonWebSignature.deserialize_json() 接收 JSON Serialization 形式的 JWS 对象时，既不检查签名也不需要密钥，就直接把 payload 作为验证成功返回，构成签名验证绕过。根因代码位于 authlib/jose/rfc7515/jws.py，在已安装的 1.8.0 制品上确认；修复版本 1.9.0。

CVE-2026-96760CVSS 9.1
受影响 Authlib prior to 1.9.0修复 1.9.0
Impact

暴露人群是所有以 Authlib 解析 JSON 序列化 JWS 做认证或授权判定的服务：攻击者提交空签名对象即可让伪造载荷被当成已验签通过，验证环节形同不存在，属可直接击穿认证判定的缺陷类型。

Action

升级 authlib 至 1.9.0；自查代码中走 deserialize_json 的校验路径，改为强制要求非空签名与密钥校验，并对依赖该库的令牌校验做回归测试。

Agno field_type 被直接交给 eval

GitHub 通告 CVE-2026-35002（CVSS 9.8，critical）：Agno 2.3.24 之前把 FunctionCall 输入字段的 field_type 参数直接传入 Python 内置 eval()，能影响该值的攻击者即可在 Agno 进程内执行任意 Python 代码，属 CWE-95 代码注入。修复版本 2.3.24。

CVE-2026-35002CVSS 9.8
受影响 Agno versions prior to 2.3.24修复 2.3.24
Impact

最易被命中的是把模型输出接进工具调用的 Agno 智能体应用：模型可控输出本身就构成来源所说的“可影响该值”的输入，一旦命中执行发生在宿主 Python 进程内，而非沙箱侧。

Action

升级 agno 至 2.3.24；对来自模型输出的 FunctionCall 字段值做类型白名单校验，禁止任何外部可控值进入 eval 路径。
