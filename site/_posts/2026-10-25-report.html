CVE-2026-96639CVSS 9.8

Impact

微软拆解 LiteLLM 投毒

Microsoft Threat Intelligence 发布 LiteLLM 1.107.0 供应链失陷分析：恶意版本借 Python startup hooks 在解释器启动阶段执行，窃取凭据并远程加载代码，微软同步给出 detections 与 mitigations。同清单内 Register 亦以「附带 RAT」跟进同事件。

2 源报道
受影响 LiteLLM 1.107.0
Impact

LiteLLM 是大量 AI 网关与 LLM 编排栈的直接依赖，装上 1.107.0 即可能向攻击者交出 API key 与环境凭据，并把远程代码加载通道带进 CI/CD 与推理服务——相当于对 AI 运维基础设施的一次成规模凭据收割。

Action

排查环境内是否存在 LiteLLM 1.107.0 的安装与运行痕迹；按微软给出的 detections 狩猎 Python startup hooks 异常加载；下线该版本、改用可信发布并轮换可能暴露的密钥。

eMudhra 中间CA私钥可还原

Qualys 发文指导识别已失陷的 eMudhra 证书：2026-10-17 披露的 CA 事件波及 eight eMudhra intermediate CA certificates，密钥生成流程缺陷可让攻击者还原私钥、签发欺诈 TLS 或代码签名证书（CVE-2026-111943、CVE-2026-111944）。涉事中间证书已被吊销，Chrome、Mozilla、Apple 等主要平台厂商已阻断。

CVE-2026-111943
受影响 eight eMudhra intermediate CA certificates修复 affected intermediates have been revoked（并被 Chrome、Mozilla、Apple 等阻断）
Impact

凡信任链经过 eMudhra 中间 CA 的 TLS 站点与代码签名产物都受波及：私钥可还原意味着伪造证书能通过校验、恶意签名可信；平台侧阻断又让未及时替换的旧链在到期前后集中出现兼容与信任故障。

Action

按 Qualys 方法清点资产中仍在使用或信任的 eMudhra 中间证书并替换；复核代码签名与 TLS 证书链，移除已吊销的八张中间证书并核对平台阻断状态。

UAC-0099
